# Glossary

Terms coined, popularised, or given a specific meaning in Medplum docs and blog. Citation = URL path on https://www.medplum.com.

- **(g)(10)** — ONC's Standardized API for Patient and Population Services criterion; certified EHRs must expose SMART-scoped FHIR APIs. (`/blog/codex-and-the-power-of-g10`)
- **AA mode** — Medplum Agent variant that immediately returns Application Accept to legacy peers. (`/docs/agent/acknowledgement-modes`)
- **AccessPolicy** — Medplum resource restricting what a membership may read/write, per type, criteria, interaction, field and write constraint. (`/docs/access/access-policies`)
- **Agent** — on-prem bridge that carries HL7v2/MLLP, ASTM and DICOM to Medplum over outbound secure WebSockets; no VPN. (`/docs/agent`)
- **agentic engineering** — building on Medplum with LLM coding agents (a.k.a. vibe coding). (`/docs/building-with-ai-coding-assistants`)
- **allowed tenants vs active tenant** — the tenants a membership may access (enforced) vs the one the UI currently filters to (application concept). (`/docs/access/tenant-selector`)
- **bedside manner (FDE)** — engineering depth delivered with empathy; trust built in how you show up. (`/blog/fde`)
- **beg bounty** — low-effort templated security "report" fishing for payment for a non-issue (Troy Hunt's term). (`/blog/security-reports`)
- **Bot** — single-file TypeScript/JS function `handler(medplum, event)` run sandboxed (Lambda by default), triggered by Subscription, `$execute`, cron or custom operation. (`/docs/bots/bot-basics`)
- **break glass** — controlled temporary emergency access to PHI, time-bound and audited. (`/docs/access/access-policies`)
- **can suggest, but not act** — guardrail pattern where AI drafts or recommends and a human performs the action. (`/docs/ai`)
- **Care Template** — Medplum Provider name for a visit-type PlanDefinition whose `$apply` yields tasks, forms and charges. (`/docs/provider/visits`)
- **ClientApplication** — OAuth client resource for apps/machines, with its own membership and access policy. (`/docs/api/project-admin/client`)
- **custom operation** — Bot + OperationDefinition exposed as a domain `$operation`; "syntactic sugar on the existing Bot execute framework". (`/blog/custom-fhir-operations`)
- **decision guide** — Medplum's discovery-question + FHIR-modeling companion document per workflow area. (`/docs/decision-guides`)
- **diagnostic catalog** — structured definitions of analytes, ranges, panels, specimens and procedures a lab offers. (`/docs/careplans/diagnostic-catalog`)
- **distributed EHR** — a headless shared FHIR data layer with specialised vertical apps on top. (`/blog/scheduling-agents-unity-ai`)
- **do-not-match list** — per-patient list of records a human has ruled out as duplicates, skipped by future matching. (`/blog/empi-implementation`)
- **durable queue** — Agent SQLite queue that commits messages to disk before ACKing; basis for retries and logical channels. (`/docs/agent/features`)
- **Fast ACK** — enhanced acknowledgement mode: commit accept first, application result later. (`/docs/agent/acknowledgement-modes`)
- **FDE (forward-deployed engineer)** — Medplum engineer embedded with customers owning scoping through support; Medplum has no PMs. (`/blog/fde`)
- **FHIR quota** — per-user weighted interaction budget (read 1, search 20, history 10, write 100) per minute. (`/docs/rate-limits`)
- **fifty-state workflow** — operating across all US states, which requires modelling licensure and credentials per state. (`/blog/digital-health-operations`)
- **headless EHR** — EHR infrastructure (data, auth, compliance, automation) without a fixed UI; builders supply the experience. (`/blog/ehr-vs-udhp`)
- **implicit availability** — time is free by default; Slots only record busy/blocked overrides. (`/docs/scheduling/defining-availability`)
- **IRA (Integrated Reporting Applications)** — IHE profile for real-time context/content sync among radiology apps via a FHIRcast Hub. (`/blog/ihe-ira-radiology-reporting`)
- **Keep the Ball in Our Court** — there is always an action to move the customer forward; waiting is a deliberate move, never a stall. (`/blog/fde`)
- **linkId contract** — linkIds as the stable interface between form and extraction logic. (`/docs/intake/intake-questionnaires`)
- **logical channel** — a partition of one HL7 channel's queue by a message-content key, ordered within, parallel across. (`/docs/agent/features`)
- **maintenance tax** — ongoing operational load of self-built healthcare infrastructure that slows product/AI work. (`/docs/ai`)
- **mapping register** — versioned index + per-rule records of source meaning, target, transformation, owner, status. (`/docs/migration/mapping-governance`)
- **Medplum Provider** — open-source EHR app on Medplum; usable as system of record, starting point, or reference implementation. (`/docs/provider`)
- **on-behalf-of** — `X-Medplum-On-Behalf-Of` header letting an admin client act as a user, preserving that user's policy and authorship. (`/docs/auth/on-behalf-of`)
- **operational FHIR store** — a store built for click-time reads, continuous writes, read-your-writes and change events, as opposed to an analytical store. (`/blog/awell-panels-case-study`)
- **parameterized access policy** — an AccessPolicy using `%variables` resolved per ProjectMembership, acting as a reusable template. (`/docs/access/access-policies`)
- **policy as code (deduplication)** — dedup rules implemented as tested, version-controlled Bot code with audit trail. (`/blog/patient-deduplication`)
- **post-deploy migration** — background index/backfill migration run after a minor upgrade; its start closes the rollback window. (`/docs/self-hosting/upgrading-server`)
- **Project** — hard-isolated container of resources, users, settings and secrets; the primary access boundary. (`/docs/access/projects`)
- **project-scoped vs server-scoped user** — User owned by one Project (clinicians/patients) vs spanning projects (developers/admins). (`/docs/user-management/project-vs-server-scoped-users`)
- **ProjectMembership** — links a User to a Project with a profile, access policy, admin flag and parameters. (`/docs/user-management`)
- **recent-first loading** — load the last ~30 days of actionable data first, hydrate older history in the background. (`/blog/large-patient-charts`)
- **Request / Event / Definition patterns** — FHIR Workflow module's three-way classification of resources. (`/blog/fhir-workflow-patterns-to-simplify-your-life`)
- **retract and correct** — mark the original `entered-in-error`, then issue a linked correction. (`/docs/communications/message-editing-and-drafts`)
- **securityContext (Binary)** — reference from which a Binary inherits access; without it a Binary is readable by anyone with Binary permission who knows its id. (`/docs/access/binary-security-context`)
- **`$set-accounts`** — operation writing `meta.accounts`/`meta.compartment`, optionally propagating across a Patient compartment; the multi-tenancy labeller. (`/docs/api/fhir/operations/set-accounts`)
- **source record / master record** — per-source copy vs combined source-of-truth patient. (`/docs/fhir-datastore/patient-deduplication/architecture-overview`)
- **Spaces** — AI assistant in Medplum Provider; a ReAct loop whose FHIR requests are executed by the UI under the user's access. (`/docs/provider/spaces`)
- **system of action** — using the FHIR store not just to record but to trigger and track agent-driven work via subscriptions. (`/blog/scheduling-agents-unity-ai`)
- **the terrible choice** — a healthcare builder must either roll all their own infrastructure for a tailored experience or bend a rigid off-the-shelf product. (`/blog/medplum-mitre-talk`)
- **top of license care** — every clinician works only at the highest level their licence allows; lower-level work routes to other roles. (`/blog/digital-health-operations`)
- **UDHP (Unified Digital Health Platform)** — an ecosystem platform fostering FHIR interoperability and APIs, as opposed to a monolithic EHR. (`/blog/ehr-vs-udhp`)
- **uniqueness gate** — disclosure-mode rule: release only if exactly one certain candidate exists and uniqueness is provable. (`/docs/api/fhir/operations/patient-match`)
